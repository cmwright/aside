# Voice-to-text prototype: plan

Goal: a minimal, open-source (MIT) push-to-talk dictation tool the owner can test locally
today. Two parts that talk over one HTTP contract:

1. `worker/` — a Cloudflare Worker (TypeScript, wrangler) that receives audio, runs
   speech-to-text at a provider the user chose, runs an LLM cleanup pass that applies the
   user's dictionary, and returns text. Runs locally with `wrangler dev`. Nothing is logged
   or stored.
2. `mac/` — a native Swift menu-bar app (SwiftUI, macOS 14+, project generated by
   xcodegen from `project.yml`). Hold a key, speak, release, text lands at the cursor.

Not in scope for this prototype: streaming preview, per-app tone, screen context,
auto-learning the dictionary, iOS, notarization, auto-update.

## Environment facts (verified 2026-09-08)

- Xcode 26.6, Swift 6.3, macOS 26.2, Apple Silicon. xcodegen 2.46 installed at
  /opt/homebrew/bin/xcodegen. Node 22, npm 10. wrangler not installed globally; use
  `npx wrangler` and pin it in `worker/package.json`.
- No code-signing identity. Builds are ad-hoc signed. Consequence: macOS ties the
  Accessibility grant to the code signature, so after each rebuild the user may have to
  remove and re-add the app in System Settings > Privacy & Security > Accessibility. The
  app must detect the missing grant and say so clearly. Document this in the README.
- No Deepgram/Groq keys in the environment. The user will paste keys into
  `worker/.dev.vars`. The Worker must support a single-key setup: Groq for both
  speech-to-text (whisper-large-v3-turbo) and cleanup, so one free Groq key is enough
  to test. Deepgram Nova-3 is the second STT provider.

## HTTP contract (both sides implement exactly this)

`POST {BACKEND_URL}/v1/audio/transcriptions`

- Auth: `Authorization: Bearer {BACKEND_TOKEN}` when the Worker has `BACKEND_TOKEN` set.
  With no token configured (local dev default), the Worker accepts unauthenticated calls.
- Body: `multipart/form-data`
  - `file`: audio, `audio/wav`, 16 kHz mono 16-bit PCM WAV, filename `audio.wav`.
  - `model`: string, ignored by the Worker but present for OpenAI-client compatibility.
    The Mac app sends `default`.
  - `dictionary`: JSON string, an array of `{ "term": string, "replacement"?: string }`.
    `term` is a word or phrase the user wants recognized as spelled. `replacement`, when
    present, means "when the transcript contains something that sounds like `term`,
    write `replacement` instead" (e.g. term "acme cloud" -> replacement "AcmeCloud").
  - `cleanup`: `"none" | "light" | "medium"`. Default `medium`.
  - `app_name`: optional string, the frontmost app's name, for future per-app tone.
    The Worker may ignore it in this prototype.
- Response `200 application/json`:
  `{ "text": string, "raw_text": string, "timing_ms": { "stt": number, "cleanup": number, "total": number } }`
  `text` is the cleaned result to paste. `raw_text` is the provider transcript before cleanup.
  On `cleanup: "none"`, `text == raw_text`.
- Errors: JSON `{ "error": string }` with 400 (bad input), 401 (bad token),
  502 (provider failure, include the provider's message), 500.
- Worker also serves `GET /health` -> `{ "ok": true, "stt": "<provider>", "cleanup": "<model or none>" }`.
- `POST {BACKEND_URL}/v1/cleanup` (added for on-device transcription): JSON body
  `{ "text": string, "dictionary"?: string|array, "cleanup"?: level, "app_name"?: string }`.
  Runs the same cleanup pass and dictionary post-pass on a transcript the client already
  has (Parakeet v3 in the Mac app). Same response shape, `timing_ms.stt` is 0.

## Worker design

- `wrangler.jsonc`, `package.json` (pinned wrangler + vitest), `src/index.ts` router,
  `src/stt/groq.ts`, `src/stt/deepgram.ts`, `src/cleanup.ts`, `src/dictionary.ts`,
  `src/prompt.ts`. Keep it small and readable.
- Config via vars/secrets: `STT_PROVIDER` (`groq` default | `deepgram`), `GROQ_API_KEY`,
  `DEEPGRAM_API_KEY`, `CLEANUP_MODEL` (default `openai/gpt-oss-120b` on Groq; `none`
  disables cleanup), `BACKEND_TOKEN` (optional).
- Deepgram: `nova-3`, `smart_format=true`, pass dictionary terms as repeated `keyterm=`
  query params (Nova-3 keyterm prompting), and `mip_opt_out=true`.
- Groq STT: `POST https://api.groq.com/openai/v1/audio/transcriptions`, model
  `whisper-large-v3-turbo`, and pass the dictionary terms joined into the `prompt` field
  (Whisper-style vocabulary hint, keep under ~200 tokens).
- Cleanup prompt: the only job is to make the transcript read like the person typed it.
  Fix punctuation, capitalization, remove filler words and false starts, apply the
  dictionary replacements exactly, keep the speaker's words and meaning, never add
  content, never answer questions in the transcript, never wrap in quotes, no preamble.
  `light` = punctuation/capitalization/dictionary only. `medium` = also fillers, false
  starts, obvious grammar. Output is the text only. Use temperature 0. Strip any leading
  or trailing quotes the model adds anyway.
- Deterministic post-pass in `dictionary.ts`: after the LLM, apply exact
  case-insensitive replacements for every entry that has a `replacement`, so the
  dictionary works even when the LLM misses one. Also apply it when cleanup is `none`.
- Never log request bodies or transcripts. Log only method, path, status, timing.
- Tests: vitest unit tests for `dictionary.ts` and prompt assembly, plus a
  `scripts/smoke.sh` that posts `test/fixtures/hello.wav` to a running `wrangler dev`
  and prints the response. Generate the fixture with macOS `say` piped through
  `afconvert` to 16 kHz mono WAV (documented in the script).

## Mac app design

- `mac/project.yml` for xcodegen. Target `Aside`, bundle id
  `com.codywright.aside`, macOS deployment target 14.0, SwiftUI app with
  `LSUIElement = true` (menu-bar only, no Dock icon). Entitlements: none needed for
  ad-hoc local builds; App Sandbox OFF (required for the Accessibility API).
  Info.plist keys: `NSMicrophoneUsageDescription`, and a Privacy string for
  Accessibility use in the onboarding copy (Accessibility has no Info.plist key; it is
  requested with `AXIsProcessTrustedWithOptions`).
- SPM dependency: `sindresorhus/KeyboardShortcuts` for the rebindable shortcut UI.
  Default trigger: hold Right Option. Must work as hold-to-talk: key down starts
  recording, key up stops and sends. Because KeyboardShortcuts is press-oriented, implement
  hold detection with an `NSEvent.addGlobalMonitorForEvents(matching: .flagsChanged)`
  monitor for the modifier-only default, and use KeyboardShortcuts for the optional
  custom combo (press to start, press again to stop). Do not use a CGEventTap in this
  prototype; that would require Input Monitoring.
- Files (SwiftUI + AppKit, no storyboards):
  - `App.swift`: `@main`, `MenuBarExtra` with a status icon that changes for idle /
    recording / processing / error, and a menu: Start/Stop, Dictionary..., Settings...,
    Permissions..., Quit.
  - `Recorder.swift`: `AVAudioEngine` input tap, convert to 16 kHz mono Int16 with
    `AVAudioConverter`, accumulate into a WAV `Data`. Handle input-format changes
    (Bluetooth headsets switch formats) by rebuilding the converter on
    `AVAudioEngineConfigurationChange`. Minimum duration guard: ignore recordings under
    300 ms.
  - `BackendClient.swift`: multipart POST per the contract, 30 s timeout, decodes the
    response, surfaces a readable error string.
  - `TextInserter.swift`: tiered insertion.
    1. Accessibility path: get the system-wide focused `AXUIElement`; if it has a
       settable `kAXSelectedTextAttribute`, set it to the text (this inserts at the
       cursor / replaces the selection).
    2. Fallback: save the current `NSPasteboard.general` contents (all types), write
       the text, post Cmd+V via `CGEvent` (key down + up, virtual key 9 with
       `.maskCommand`), wait 250 ms, restore the previous pasteboard contents.
    3. If both fail, leave the text on the pasteboard and show an error state with the
       message "Copied to clipboard; paste manually".
    Add a leading space when the character before the insertion point is a letter or
    digit and the text starts with a letter; skip when the Accessibility API cannot read
    context.
  - `Dictionary.swift` + `DictionaryView.swift`: `[DictionaryEntry]` persisted as JSON
    in `~/Library/Application Support/Aside/dictionary.json`. Table with add /
    edit / delete, columns Term and Replacement (optional). Import/export as JSON.
  - `Settings.swift` + `SettingsView.swift`: backend URL (default
    `http://localhost:8787`), backend token, cleanup level, shortcut recorder,
    "Play sound on start/stop" toggle. Persist in `UserDefaults`.
  - `Permissions.swift` + `PermissionsView.swift`: checklist for Microphone and
    Accessibility with live status and buttons that open the right System Settings pane
    (`x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility`).
    Explain the ad-hoc-signing re-grant issue in one sentence.
  - `StatusOverlay.swift`: small non-activating floating `NSPanel` near the bottom
    center of the screen showing "Listening" / "Transcribing" / the error text. Never
    steals focus (`.nonactivatingPanel`, `canBecomeKey = false`).
  - `Log.swift`: `os.Logger` with subsystem `com.codywright.aside`. Never log
    transcript text at default level.
- Frontmost app name from `NSWorkspace.shared.frontmostApplication` captured at key-down,
  sent as `app_name`.
- Build must succeed with:
  `cd mac && xcodegen generate && xcodebuild -project Aside.xcodeproj -scheme Aside -configuration Debug CODE_SIGN_IDENTITY=- CODE_SIGNING_REQUIRED=NO CODE_SIGNING_ALLOWED=NO build`
  Add `mac/build.sh` that runs that and prints the path of the built `.app`, and
  `mac/run.sh` that builds then `open`s it.
- Swift 6 language mode is fine but avoid fighting strict concurrency: mark AppKit-touching
  types `@MainActor`, keep the recorder's audio callback free of actor hops (append to a
  lock-protected buffer).
