# Aside for macOS

The menu-bar app. SwiftUI, macOS 14+, Apple Silicon, project generated by
[xcodegen](https://github.com/yonaskolb/XcodeGen) from `project.yml`. User-facing setup is
in the [root README](../README.md); this file is about building, signing and releasing.

## Build and run

```sh
brew install xcodegen
./build.sh    # xcodegen generate + xcodebuild Debug; prints the .app path
./run.sh      # build, then launch
```

`build.sh` exports `DVT_PLUG_INS_TO_IGNORE=com.apple.dt.IDESimulatorFoundation` because a
Mac whose Xcode never ran `sudo xcodebuild -runFirstLaunch` cannot start xcodebuild
otherwise. It is a no-op on a healthy install.

Tests (the Mac unit tests also cover the iOS hand-off protocol in `../ios/Shared`):

```sh
DVT_PLUG_INS_TO_IGNORE=com.apple.dt.IDESimulatorFoundation xcodebuild \
  -project Aside.xcodeproj -scheme Aside -destination 'platform=macOS,arch=arm64' \
  -derivedDataPath build test
```

## Signing

`Signing.xcconfig` (git-ignored; `build.sh` creates it from `Signing.xcconfig.example`)
holds the team ID and identities. Three levels:

1. **Ad-hoc, no Apple account.** The default. Works, but macOS ties the Accessibility grant
   to the code signature, so after every rebuild you may have to remove Aside from
   System Settings → Privacy & Security → Accessibility and add it again. The app's
   Permissions window shows live status.
2. **Apple Development, free Apple ID.** Sign into Xcode (Settings → Accounts), put the
   Team ID in `DEVELOPMENT_TEAM`, set `DEBUG_SIGN_IDENTITY = Apple Development`. Grants
   survive rebuilds.
3. **Developer ID, paid program.** Create a *Developer ID Application* certificate in
   Xcode → Settings → Accounts → Manage Certificates. Setting `DEBUG_SIGN_IDENTITY` to it
   as well gives dev builds the same identity as releases.

Entitlements are generated by xcodegen from `project.yml` (`entitlements: properties:`);
the only one is microphone access, which the hardened runtime requires. App Sandbox is
off because the Accessibility API needs it off, which is also why the Mac App Store is
not an option.

## Releasing

One-time: store notarization credentials with an app-specific password from
https://account.apple.com:

```sh
xcrun notarytool store-credentials aside-notary --apple-id you@example.com --team-id TEAMID
```

Sparkle signs updates with an EdDSA key that lives in the release machine's keychain;
the public half is `SUPublicEDKey` in `project.yml`. Generate a pair once with
`build/SourcePackages/artifacts/sparkle/Sparkle/bin/generate_keys` and paste the public key.

Each release:

```sh
# bump MARKETING_VERSION / CURRENT_PROJECT_VERSION in project.yml, then
./release.sh              # Release build, Developer ID + timestamp, re-signs Sparkle's
                          # nested components, notarizes, staples, writes build/releases/appcast.xml
./publish.sh 0.2.0        # GitHub Release with the zip and appcast (repo must be public)
```

Installed copies poll `https://github.com/cmwright/aside/releases/latest/download/appcast.xml`
daily and offer the update.

## Source map

- `App.swift` — `@main`, the menu, `AppController` (trigger, recording, the
  transcription/cleanup pipeline, insertion).
- `Trigger.swift` — hold vs double-tap state machine for Right Option (pure, tested).
- `Recorder.swift` — AVAudioEngine capture to 16 kHz mono PCM, streaming into Parakeet
  while the key is held.
- `LocalTranscriber.swift` — Parakeet v3 via FluidAudio. `AppleCleanup.swift` — Apple's
  on-device model via FoundationModels with guided output and a similarity guard.
- `DirectClient.swift`, `Providers.swift`, `APIKeyStore.swift` — OpenAI-compatible
  providers called directly; keys in the keychain.
- `BackendClient.swift` — the optional Worker. `CleanupPrompt.swift` — the cleanup
  instructions, kept in step with `../worker/src/prompt.ts`. `DictionaryReplacer.swift` —
  the deterministic post-pass, a port of the Worker's.
- `TextInserter.swift` — Accessibility API first, clipboard paste second.
- `Dictionary*.swift`, `Settings*.swift`, `History*.swift`, `Permissions*.swift`,
  `StatusOverlay.swift`, `AsideIcon.swift` (the menu bar glyph, drawn in code).
- `scripts/make-appicon.swift` — renders `Resources/AppIcon.icns` from the same glyph.
