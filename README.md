# voice-to-text

Push-to-talk dictation for macOS. Hold a key, speak, release — clean text lands at your
cursor in whatever app you are in.

Two halves, one HTTP contract:

- **`worker/`** — a Cloudflare Worker (TypeScript, wrangler). It takes the audio, runs
  speech-to-text at the provider you chose, runs an LLM cleanup pass that applies your
  personal dictionary, and returns the text. It stores nothing and logs nothing but
  method, path, status and timing.
- **`mac/`** — a SwiftUI menu-bar app (macOS 14+, project generated by xcodegen). It
  records while you hold the key, posts the audio to the Worker, and inserts the result
  at the cursor.

Everything runs locally: `wrangler dev` on your machine, the app talking to
`http://localhost:8787`. The only thing that leaves your Mac is the audio going to your
speech-to-text provider.

## 10-minute setup

You need: macOS 14+, Xcode, Node 22+, [xcodegen](https://github.com/yonaskolb/XcodeGen)
(`brew install xcodegen`), and a free [Groq](https://console.groq.com/keys) API key.
One Groq key covers both speech-to-text and cleanup.

### 1. Start the Worker

```sh
cd worker
npm install
cp .dev.vars.example .dev.vars   # then paste your GROQ_API_KEY into it
npx wrangler dev                 # http://localhost:8787
```

Check it:

```sh
curl http://localhost:8787/health
# {"ok":true,"stt":"groq","cleanup":"openai/gpt-oss-120b"}
```

Leave this running in its own terminal.

`.dev.vars` (git-ignored) holds the configuration. Every variable is documented in
[`worker/.dev.vars.example`](worker/.dev.vars.example):

| Variable | Default | What it does |
| --- | --- | --- |
| `STT_PROVIDER` | `groq` | `groq` (Whisper large v3 turbo) or `deepgram` (Nova-3). |
| `GROQ_API_KEY` | — | Needed for Groq speech-to-text and for cleanup on either provider. |
| `DEEPGRAM_API_KEY` | — | Only when `STT_PROVIDER=deepgram`. |
| `CLEANUP_MODEL` | `openai/gpt-oss-120b` | Groq chat model for cleanup; `none` returns the raw transcript. |
| `BACKEND_TOKEN` | unset | When set, callers must send `Authorization: Bearer <token>`. Leave empty locally. |

### 2. Build and run the Mac app

```sh
cd mac
./run.sh          # xcodegen generate + xcodebuild + open the built .app
```

`./build.sh` does the build alone and prints the path of the `.app`. The app has no Dock
icon; look for its icon in the menu bar.

### 3. Grant permissions

On first launch the app asks by itself: it triggers the Microphone prompt, triggers the
Accessibility prompt and opens its own **Permissions** window. You can reopen that window
any time from the menu-bar icon. Two grants are needed:

- **Microphone** — macOS asks the first time the app launches, and again if you hold the
  key before answering ("Allow microphone access, then hold the key again").
- **Accessibility** — System Settings → Privacy & Security → Accessibility, add the app
  and switch it on. This is what lets the app see the Right Option key and type into other
  apps. The app polls once a second while the grant is missing and re-arms its key monitor
  the moment the grant lands, so there is no need to relaunch it.

There is no code-signing identity in this project, so builds are ad-hoc signed. macOS ties
the Accessibility grant to the code signature, which changes on every rebuild: **after a
rebuild you may have to remove the app from the Accessibility list with `-` and add it
again.** The Permissions window shows live status so you can see when this has happened.

### 4. Dictate

Hold **Right Option**, speak, release. Or double-tap it to keep listening hands-free and tap once more to stop. The overlay near the bottom of the screen shows
"Listening" then "Transcribing"; the text is inserted at your cursor. You can change the
shortcut in **Settings...**, along with the backend URL, backend token and cleanup level.

Add the words you say that transcription gets wrong under **Dictionary...**: a *term*
("hyper comply") with an optional *replacement* ("HyperComply"). Terms are sent to the
speech-to-text provider as vocabulary hints, given to the cleanup model as instructions,
and — for entries with a replacement — applied one final time as a deterministic
case-insensitive, word-boundary-safe search and replace, so a replacement lands even if
the model misses it.

## On-device transcription (optional)

Settings → Transcription → Engine → **On this Mac (Parakeet v3)**. The app downloads
NVIDIA's Parakeet TDT 0.6B v3 (about 470 MB, cached under
`~/Library/Application Support/FluidAudio/Models`) and runs it on the Neural Engine via
[FluidAudio](https://github.com/FluidInference/FluidAudio). Audio never leaves the Mac.
The transcript is still sent to the Worker's `POST /v1/cleanup` for the LLM cleanup pass
and dictionary replacements, unless Cleanup is **None** and no dictionary entry has a
replacement, in which case nothing leaves the Mac at all. The first load after launch
takes a while (CoreML compiles the model); the overlay says so.

Once the model is loaded, transcription runs while you are still holding the key:
FluidAudio's sliding-window engine decodes the audio in 11 s windows with 2 s of context
on each side (the same layout its whole-file path uses), so on key-up only the last few
seconds are left to decode. The overlay says "Finishing up". If the model is still loading
when you press the key, the whole recording is transcribed after key-up as before.

## The HTTP contract

`POST {BACKEND_URL}/v1/audio/transcriptions`, `multipart/form-data`:

| Field | Value |
| --- | --- |
| `file` | `audio/wav`, 16 kHz mono 16-bit PCM, filename `audio.wav` |
| `model` | ignored by the Worker; present for OpenAI-client compatibility |
| `dictionary` | JSON string: `[{"term": "...", "replacement": "..."}]` (`replacement` optional) |
| `cleanup` | `none` \| `light` \| `medium` (default `medium`) |
| `app_name` | optional; the frontmost app, for future per-app tone |

`Authorization: Bearer <BACKEND_TOKEN>` when the Worker has a token configured; with no
token configured it accepts unauthenticated calls (the local-dev default).

Response `200 application/json`:

```json
{
  "text": "The cleaned text to paste.",
  "raw_text": "the raw provider transcript",
  "timing_ms": { "stt": 412, "cleanup": 380, "total": 802 }
}
```

With `cleanup: "none"`, `text` is `raw_text` plus dictionary replacements.

Errors are `{ "error": "..." }` with **400** (bad input — a missing/empty `file`, an
unparseable `dictionary`, or a `cleanup` value that is not one of the three levels),
**401** (bad token), **502** (provider failure — the provider's own message is included)
or **500**.

`GET /health` → `{ "ok": true, "stt": "groq", "cleanup": "openai/gpt-oss-120b" }`.

`POST /v1/cleanup` with a JSON body `{ "text", "dictionary"?, "cleanup"?, "app_name"? }`
runs only the cleanup pass and dictionary post-pass on a transcript the client already
has. Same response shape as the audio route, with `timing_ms.stt` = 0.

Cleanup levels: `light` fixes punctuation, capitalization and the dictionary only;
`medium` also drops filler words and false starts and fixes obvious grammar slips. Both
run at temperature 0 and are told never to add content and never to answer a question that
appears in the transcript.

## Signing and releasing

Debug builds are ad-hoc signed by default, which works with no Apple account but makes
macOS re-ask for Accessibility after every rebuild. `mac/Signing.xcconfig` (git-ignored,
created from `Signing.xcconfig.example` on first build) controls signing:

1. **Stable local builds, free.** Sign into Xcode with your Apple ID (Settings → Accounts).
   Put the Team ID it shows in `DEVELOPMENT_TEAM` and set
   `DEBUG_SIGN_IDENTITY = Apple Development`. Rebuilds now keep their permissions.
2. **Distributable builds, $99/year.** Enroll in the Apple Developer Program, then in
   Xcode → Settings → Accounts → Manage Certificates create a **Developer ID Application**
   certificate. Create an app-specific password at https://account.apple.com and store it:
   `xcrun notarytool store-credentials aside-notary --apple-id you@example.com --team-id TEAMID`.
   Then `./mac/release.sh` builds a hardened-runtime Release app, signs it, notarizes it,
   staples the ticket, and leaves `mac/build/Aside-<version>.zip` ready to publish.

The app cannot go on the Mac App Store: the Accessibility API needs the App Sandbox off.
Builds are Apple Silicon only (on-device Parakeet needs the Neural Engine).

## Developing

```sh
cd worker
npx vitest run     # unit tests for the dictionary post-pass and prompt assembly
npx tsc --noEmit   # typecheck
./scripts/smoke.sh # generates test/fixtures/hello.wav with say + afconvert, then POSTs it
```

`scripts/smoke.sh` needs `npx wrangler dev` running in another terminal; it honours
`BACKEND_URL`, `BACKEND_TOKEN` and `CLEANUP`.

Worker source map: `src/index.ts` (router, auth, timing), `src/stt/groq.ts`,
`src/stt/deepgram.ts`, `src/cleanup.ts`, `src/dictionary.ts` (parsing + the deterministic
replacement pass), `src/prompt.ts` (all prompt text), `src/types.ts`.

Deploying the Worker to Cloudflare is optional: `npx wrangler deploy`, then
`npx wrangler secret put GROQ_API_KEY` (and `BACKEND_TOKEN` — set one if the Worker is
reachable from the internet), and point the app's backend URL at the deployed URL.

## Known limitations

- Prototype quality: no streaming preview, no per-app tone, no screen context, no
  auto-learning of the dictionary, no iOS, no notarization, no auto-update.
- Ad-hoc signing means the Accessibility grant is lost on rebuild (see above), and the app
  will not run on another Mac without being rebuilt there.
- Insertion is best-effort: the Accessibility path first, then a Cmd+V paste with the
  pasteboard saved and restored. If both fail, the text is left on the clipboard and the
  app says "Copied to clipboard; paste manually". Apps with unusual text views (some
  terminals, some Electron apps) may only work via the paste path.
- Audio goes to your speech-to-text provider (Groq or Deepgram) over the network. Deepgram
  requests are sent with `mip_opt_out=true`. Nothing is stored or logged by the Worker,
  but the providers have their own policies.
- The whole recording is sent after you release the key, so latency scales with clip
  length — this is not designed for minute-long monologues. A recording that never sees a
  key-up (screen lock, a secure-input field, sleep) is stopped and sent after 90 seconds.
- One user, one machine, no rate limiting. Set `BACKEND_TOKEN` before exposing the Worker.
