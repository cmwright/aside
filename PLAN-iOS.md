# Aside for iPhone: plan

Goal: the Wispr Flow iPhone concept in our own app. A tiny keyboard is the front end; the
main app does the recording, transcription and cleanup; the keyboard inserts the result at
the cursor. Same engines as the Mac app: Parakeet v3 on-device or the Worker for speech,
Apple's on-device model or the Worker for cleanup, dictionary post-pass in Swift.

## The hard constraint this design is built around

iOS keyboard extensions cannot use the microphone (true since iOS 8, still true in iOS 26,
with or without Full Access). Every dictation keyboard on iPhone, Wispr included, records
in its main app. What makes Wispr feel seamless is that the app keeps an audio session
alive in the background ("Flow Session"), so after one app-switch per session every
dictation is keyboard-only: tap, speak, tap, text appears.

## Repo layout

```
ios/
  project.yml            xcodegen spec: app target Aside, extension target AsideKeyboard
  Signing.xcconfig(.example)  DEVELOPMENT_TEAM etc, git-ignored real file (reuse mac's pattern)
  build.sh               generic iOS device build, CODE_SIGNING_ALLOWED=NO (no simulator on this Mac)
  README.md              install on a phone via Xcode, enable keyboard + Full Access, first session
  App/                   iOS app sources
  Keyboard/              keyboard extension sources
  Shared/                Foundation-only code compiled into BOTH targets (and the Mac test target)
```

Reuse the Mac app's platform-neutral files by referencing them from `ios/project.yml` with
relative paths (`../mac/Sources/<file>`), do not copy them:

- `CleanupPrompt.swift`, `DictionaryReplacer.swift`, `BackendClient.swift`, `Log.swift`
  (Foundation / os only)
- `Dictionary.swift`, `Settings.swift` (Foundation + SwiftUI; `DictionaryStore(fileURL:)` and
  `AppSettings(defaults:)` already take injectable storage, use the App Group for both)
- `LocalTranscriber.swift` (FluidAudio, works on iOS 17+), `AppleCleanup.swift`
  (FoundationModels, guard with `#available(iOS 26, *)`; `#if canImport` is already there)
- `PCMCapture.swift` (the WAV writer and the realtime PCM sink; each app keeps its own
  recorder around it, because the phone's must survive interruptions and route changes)
- `Trigger.swift` (the hold / tap gesture state machine, and the tap preference the
  keyboard extension reads straight from the App Group suite)

If one of those needs a platform guard to compile on iOS, make the smallest possible
`#if os(macOS)` / `#if canImport(AppKit)` edit and list it in the report. Do not otherwise
edit anything under `mac/` except `mac/project.yml` (see Tests).

## Identifiers

- App: `com.codywright.aside.ios`, display name Aside. Keyboard: `com.codywright.aside.ios.keyboard`.
- App Group: `group.com.codywright.aside` on both targets (entitlements files, generated by
  xcodegen `entitlements: properties:` the same way mac/project.yml does it; an entry with
  no properties writes an empty file).
- URL scheme `aside://` on the app. Keyboard opens `aside://session/start`.
- Deployment target iOS 17.0, iPhone only, arm64 only (FluidAudio needs it).
- Info.plist on the app: `NSMicrophoneUsageDescription`, `UIBackgroundModes: [audio]`,
  `CFBundleURLTypes` for `aside`. On the keyboard: `NSExtension` with
  `RequestsOpenAccess: true`, `PrimaryLanguage: en-US`, `IsASCIICapable: false`.

## Hand-off protocol (ios/Shared/AsideIPC.swift, Foundation only, unit-tested on macOS)

Everything goes through the App Group container directory. Files, not UserDefaults, so
there is no cross-process caching ambiguity; every write is atomic (`.atomic`).

- `session.json`: `{ "active": Bool, "startedAt": Date, "expiresAt": Date?, "pid": Int }`.
  Written by the app when a session starts, ends or expires. The keyboard treats a missing
  or expired file as "no session".
- `commands/<uuid>.json`: `{ "id": uuid, "action": "start" | "stop" | "cancel", "at": Date,
  "contextBefore": String? }`. Written by the keyboard. `contextBefore` is the last ~40
  characters before the cursor (from `textDocumentProxy.documentContextBeforeInput`) so the
  app can decide on a leading space.
- `results/<uuid>.json`: `{ "id": uuid, "status": "recording" | "processing" | "done" | "failed",
  "text": String?, "rawText": String?, "error": String?, "engine": String?, "cleanup": String?,
  "sttMs": Int?, "cleanupMs": Int? }`. Written by the app, keyed by the command id.
- Wake-ups: Darwin notifications `com.codywright.aside.command` (keyboard -> app) and
  `com.codywright.aside.result` (app -> keyboard) via `CFNotificationCenterGetDarwinNotifyCenter`.
  Both sides ALSO poll the directory on a 250 ms timer while a dictation is in flight,
  because Darwin notifications are best-effort.
- Housekeeping: the app deletes command and result files older than 10 minutes on session start.
- Provide `AsideIPC` with typed `read/write` helpers, a `Clock` injection point for tests,
  and pure functions for: session validity, leading-space decision
  (`needsLeadingSpace(contextBefore:text:)`, same rule as the Mac inserter), and listing
  pending commands in order.

## The app (ios/App)

SwiftUI, iOS 17. Screens, keep them plain:

1. **Home**: session status card (Inactive / Active until HH:MM / Expired), a big
   **Start Session** / **End Session** button, and a hold-to-talk button that works
   standalone (record, transcribe, show the text with Copy) so the app is useful on its own
   and the pipeline can be tested without the keyboard. Below it, the last result.
2. **Dictionary**: list with add/edit/delete, same JSON file format as the Mac
   (`DictionaryCodec`), stored in the App Group so the keyboard could read it later.
3. **Settings**: transcription engine (On this iPhone / Cloud), cleanup level
   (None/Light/Medium), cleanup engine (Apple on-device / Cloud), backend URL + token +
   Test Connection, session length (5 min / 15 min / 1 hour / until I end it), model status
   lines (Parakeet download state, Apple model availability with reason).
4. **Recent**: last 50 dictations with raw vs final, like the Mac window.

Session engine (`ios/App/SessionController.swift`, `@MainActor`):

- Start: configure `AVAudioSession` (`.playAndRecord`, mode `.default`, options
  `[.mixWithOthers, .allowBluetooth, .defaultToSpeaker]`), activate it, start the
  `Recorder` engine with a listener that DISCARDS samples unless a dictation is in flight
  (privacy: nothing is buffered between dictations). Keeping the engine running is what
  keeps the app alive in the background under the `audio` background mode. Write
  `session.json`. Schedule expiry with a `Task` sleep; on expiry stop everything, write
  `active: false`, and post a local notification "Aside session ended" (request
  notification permission the first time).
- Handle `start` command: begin buffering into a fresh `PCMSink`, write result
  `recording`. Handle `stop`: take the buffer, write `processing`, run the pipeline
  (Parakeet or Worker -> cleanup engine -> `DictionaryReplacer`), write `done` with text, or
  `failed` with a readable error. Handle `cancel`: drop the buffer.
- Watchdog: a dictation longer than 90 s is stopped and processed.
- If the app is launched from `aside://session/start`, start the session immediately and
  show Home with a banner "Session started. Go back to your app and switch to the Aside
  keyboard." (iOS has no public API to return to the previous app; the status-bar back
  breadcrumb does that.)
- Reuse `AppController`-style structure from the Mac app where it fits, but keep it iOS-native.

Pipeline: identical to the Mac `runCleanup` flow. Parakeet via `LocalTranscriber`
(`prepare()` on launch when selected; show download progress state). Apple cleanup via
`AppleCleanup` with the guided-generation and similarity guard already in that file. Worker
via `BackendClient` (`transcribe` for audio, `cleanup` for text). Timing captured per stage.

## The keyboard (ios/Keyboard)

`UIInputViewController` subclass hosting a SwiftUI view. Height about 220 pt. Layout:

- Top status line: "Aside" plus state: **Start a session** (tap opens the app via
  `aside://session/start` using the extension's `openURL` responder-chain trick),
  **Ready**, **Listening…**, **Transcribing…**, or the error text.
- Center: one large round mic button. Hold-to-talk (touch down = `start`, touch up = `stop`)
  AND double-tap to latch, single tap to stop, mirroring the Mac trigger. Reuse
  `mac/Sources/Trigger.swift` (Foundation only) for the gesture state machine.
- Bottom row: globe (next keyboard, `advanceToNextInputMode`, hidden when
  `needsInputModeSwitchKey` is false), space, backspace (with press-and-hold repeat),
  return. Nothing else; this keyboard is for dictating, not typing.
- On `done` result: insert with `textDocumentProxy.insertText`, adding a leading space per
  `AsideIPC.needsLeadingSpace`. On `failed`: show the error for 4 s.
- Without Full Access the App Group is unreadable: detect it (`hasFullAccess`) and show
  "Turn on Allow Full Access in Settings > General > Keyboard > Keyboards > Aside" instead
  of the mic button.
- Memory: keyboard extensions are killed above roughly 50 MB. No FluidAudio, no
  FoundationModels, no networking in the extension. Only `ios/Shared` and `Trigger.swift`.

## Signing and building

- `ios/Signing.xcconfig.example` -> `ios/Signing.xcconfig` (git-ignored, add to root
  .gitignore) with `DEVELOPMENT_TEAM = 44F896V7UJ` prefilled in the example's comment.
  `CODE_SIGN_STYLE = Automatic` for iOS (device installs need Xcode-managed profiles with
  the App Group capability; Xcode registers the group automatically).
- `ios/build.sh`: `xcodegen generate` then
  `xcodebuild -project Aside.xcodeproj -scheme Aside -configuration Debug -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO build`
  with the same `DVT_PLUG_INS_TO_IGNORE` export the Mac build uses. Both targets must
  compile. There is no usable iOS simulator on this machine, so this is the verification.
- The owner installs on the phone from Xcode: open `ios/Aside.xcodeproj`, pick the phone,
  Run. Document trusting the developer certificate on the phone and enabling the keyboard.

## Tests

Add `ios/Shared/AsideIPC.swift` and `ios/Tests/AsideIPCTests.swift` to the Mac test target
by adding path entries to `mac/project.yml` (`VoiceToTextTests`/`AsideTests` target sources:
`- path: ../ios/Shared` and `- path: ../ios/Tests`). That is the only permitted edit under
`mac/`. Tests cover: session validity across expiry, command/result round trip through a
temp directory, ordering of pending commands, housekeeping, and the leading-space rule.
Run them with the Mac test command in `mac/README.md`.
